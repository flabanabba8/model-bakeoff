# Model Bakeoff

Create a fixed set of prompts and literal exact-match or substring checks. Run individual tasks against an explicitly selected local Ollama-compatible model, or record externally obtained answers. Local runs measure wall-clock latency and retain the server's reported input/output token counts when available. Reports show missing tasks, timing/token sample counts, and attempt status. Inspect one recorded prompt and answer at a time for qualitative comparison. The task set is fingerprinted to detect accidental changes.

Local model calls are restricted to a loopback HTTP server. Each tool call sends one prompt; one pending call per bakeoff is allowed. Interrupted or malformed responses are marked unknown and never automatically retried. An explicit recovery can mark a pending attempt from this version unknown after its local execution lock is released; the server might still be generating and must be reviewed. After reviewing an unknown attempt, explicitly abandon it before choosing a new run. Older pending attempts without an execution lock require a new bakeoff. The plugin does not manage model downloads or stop a server; loading a model can consume CPU, GPU memory and time.

Literal checks are not semantic quality judgments. A seed and zero temperature are requested, but reproducibility and model identity depend on the server and model implementation. Wall time includes model loading and transport, so compare equivalent warm/cold conditions. Manual results and timings are user-supplied, and provider token counts are reported rather than independently verified. Prompts and answers remain in the private Hermes plugin data directory and may contain sensitive content.

Nine tests include a real local HTTP protocol fixture, failure recovery and remote-endpoint rejection. No actual Ollama model or production benchmark has been run.
